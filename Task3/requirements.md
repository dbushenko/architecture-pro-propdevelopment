1. Требования к безопасности
----

* TLS 1.3 для передачи данных
* Шифрование биометрических данных при хранении (AES-256)
* Подписание всех документов NDA с партнером, чтобы не нарушались никакие законы РФ

2. Протоколы аутентификации и авторизации
----

* SAML для сервис-сервис взаимодействия

3. Как будет организовано взаимодействие между системами предприятия и внешней платформой
----

1. Мобильное приложение *Витрина сервисов для собственников* будет доработана для подержки новых функций *Интеллектуальный домофон* и *Интеллектуальный шлагбаум*. Взаимодействие с бэкендом никак не меняется.

2. Бэкенд *tenant-core-app* и его БД *tenant-core-bd* будут доработаны для поддержки новых функций. При этом сами функции бэкенд не реализовывает, а полностью делегирует их в *smart-home-gateway*, запросы идут по REST.

3. В *группе сервисов ЖКУ* разрабатывается микросервис *smart-home-gateway*, который является по сути адаптером для API партнерских сервисов по управлению устройствами домофонов и шлагбаумов. Кроме того, когда из партнерских сервисов приходят данные для сверки (биометрия, фотография автомобильного номера), *smart-home-gateway* направляет запросы на сверку на два новых микросервиса: *biometric-service* и *car-number-service*.

4. Микросервисы *biometric-service* и *car-number-service* умеют сравнивать переданные им данные с хранимыми в БД *crm-tenant-db*.

5. *CRM* и его БД *crm-tenant-db* дорабатываются для подержки биометрии клиенитов и номеров автомобилей.
